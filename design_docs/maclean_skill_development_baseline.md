# MacLean SKILL 开发基准

**文档版本：1.0 · 日期：2026-10-19**

本文面向开发者和编程 Agent，作为独立实现 MacLean 的规范。旧版本代码可以参考，但不作为架构约束；此前发现的漏扫、误分类和执行失败必须转化为验收案例。

## 1. 产品目标与运行边界

MacLean 是一个由 AI 客户端调用的 macOS 清理技能，采用：

**固定规则库 → 定向扫描 → 清理报告 → 批量批准 → 确定性执行 → 结果报告。**

研发阶段研究目录用途、删除后果和恢复成本；使用阶段直接匹配已经验证的规则。AI 负责理解用户需求、调查未覆盖对象和解释结果，不对每个已知缓存重新决定是否可删。

首版只交付三类清理能力：

| 类别 | 范围 |
|---|---|
| macOS 应用 | 标准缓存、诊断日志、已验证的应用专用缓存 |
| AI 客户端 | Codex、Claude Code、Cursor 的缓存、日志、安装暂存和符合保留规则的旧版本 |
| 开发项目 | 用户指定项目中的构建、测试、检查和字节码缓存，以及 npm、uv 等工具的下载缓存 |

首版不包含项目退休、worktree 删除、CLI 来源账本、工具卸载、隔离恢复、定时维护、系统瘦身、备份和个人文件清理。

### 宿主兼容目标

所有宿主调用同一份规则和清理核心，不维护“本地版”和“ChatGPT 版”两套算法。

| 宿主能力 | 接入方式 |
|---|---|
| 可以执行本机命令的 AI 客户端 | 安装技能，直接调用 Mac 上的清理核心 |
| ChatGPT 网页版等远程客户端 | 加载技能，通过用户已安装并授权的 Mac 连接器调用相同核心 |
| 无法访问 Mac 的客户端 | 展示接入要求，不能声称已经扫描或清理 |

“任意 AI 客户端”指符合上述能力要求的宿主，不表示上传一个文件就能获得本机权限。技能安装、插件安装和连接器授权是独立步骤；按宿主支持的方式提供技能目录、ZIP 或插件包装。[OpenAI 技能分发说明](https://learn.chatgpt.com/docs/build-skills)、[技能与连接器权限边界](https://learn.chatgpt.com/docs/enterprise/skills)

**技术默认值：**Mac 上运行 Python ≥3.10，清理核心仅使用标准库和 SQLite；不增加独立模型服务、API Key 或专用 MCP 服务。缺少 Python 或连接器能力时报告具体缺项，不自动安装依赖。

## 2. 删除原则与规则库

### 删除原则

1. **已验证的真缓存默认选中。** 重新下载、编译、本地确定性生成、近期创建、多人共享或创建者未知，都不能单独成为保留理由。
2. **删除资格与执行时机分开。** 正在使用不等于不可清理；由适配器决定在线清理、协议协调或等待当前任务结束。
3. **不以释放空间换取额外模型费用。** 已知会增加付费推理、付费 embeddings 重建，或损失有价值的推理复用的数据不默认清理。AI 重新生成不属于普通本地重建。
4. **费用判断在规则研发阶段完成。** 普通日志、下载和编译缓存不要求逐次证明“绝对零风险”；存在具体推理依赖且尚未查明的对象进入待研究。
5. **唯一内容和持久状态保留。** 源码、会话、凭据、配置、用户成果、未同步数据、当前工具安装不混入普通缓存。
6. 日志可以清理，但必须说明删除的是不可恢复的诊断历史，不能称为可重建内容。

### 三类规则的扫描基准

**macOS 应用规则**

默认入口为用户 Library 中的 Caches、Logs，以及沙盒和应用组中对应的缓存、日志目录。Application Support 仅匹配已验证的具体叶目录。

Apple 明确将 Caches 定义为可再生成的数据，并要求应用不依赖缓存持续存在；Application Support 则可能包含用户数据。因此前者可采用通用规则加明确例外，后者采用应用或框架专用规则。[Apple 目录规范](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/FileSystemProgrammingGuide/MacOSXDirectories/MacOSXDirectories.html)

必须覆盖常见浏览器、Electron 应用、编辑器的下载、渲染和代码缓存。Cookies、登录信息、历史记录、Local Storage、IndexedDB 等不随缓存清理。不得使用“目录名包含 cache/log”作为唯一删除依据。

**AI 客户端规则**

按工具分别维护规则。Codex 优先查官方开源实现；Claude Code 和 Cursor 使用官方文档、公开安装器及可重复验证的布局。

必须研究并记录：

- 日志和应用渲染缓存；
- 下载与安装暂存；
- 旧运行时的当前版本、回退版本和发布关系；
- 会话、上下文、工具配置及模型费用依赖。

Codex 公开 CLI 源码不能自动证明桌面客户端所有目录的用途。Claude Code 的配置和调试日志路径支持重定向，规则必须允许显式根目录覆盖。[Claude Code 路径配置资料](https://code.claude.com/docs/en/env-vars)

旧版本只在当前版本关系可验证时回收；保留当前版本及最新两个有效版本的并集。无法验证的目录显示具体缺口，不将整个工具目录当作缓存。

**开发项目规则**

项目根目录必须由用户指定，不默认递归扫描整个主目录。首批覆盖：

- Next.js 的构建缓存；
- Cargo 增量编译缓存；
- 有对应源码的 Python 字节码；
- pytest、Ruff 缓存；
- npm/npx、uv 原生缓存域；
- 可验证的 Playwright、Puppeteer 自动下载副本。

项目是否存在未提交修改，不影响独立缓存的删除资格。已跟踪源码、修改过的依赖环境和部署产物不按普通缓存处理。优先使用包管理器支持的原生清理接口。

### 规则文件契约

规则以随包发布的 JSON 文件维护。每条至少包含：

| 字段 | 含义 |
|---|---|
| `id`、`version`、`category` | 稳定标识、规则版本、所属类别 |
| `roots`、`match`、`exclude` | 根目录、相对路径模式、明确例外 |
| `purpose`、`identity_checks` | 目录用途及必要的布局验证 |
| `action`、`execution_protocol` | 类型化动作和执行方式 |
| `recovery`、`impact` | 恢复方法与删除影响 |
| `inference_cost_effect` | 无预期增加、已知增加、具体依赖待核查 |
| `sources`、`tested_versions` | 官方依据、源码提交和验证范围 |
| `status` | 已启用或待研究 |

扫描和显式路径检查必须共用同一规则库。规则文件不得包含任意 shell 代码。待研究规则可以出现在覆盖报告中，但不能生成删除动作。

新增规则须经过“依据核查 → 正反例 fixture → 本机只读验证 → 执行动作测试”，随后随版本发布；不在用户运行时自动下载或启用新规则。

## 3. 技能结构、核心接口与宿主接入

技能包由四部分组成：

- `SKILL.md`：触发条件、工作流程、工具调用和结果解释。
- `rules/`：规则数据与证据引用。
- `scripts/`：统一 CLI、扫描器、计划器、执行器和校验工具。
- `assets/`：本地 HTML 报告模板。

产品名为 MacLean，安装标识保持 `macos-disk-auditor`。正式入口为 `scripts/maclean.py`。

### 最小命令接口

| 命令 | 职责 |
|---|---|
| `capabilities` | 返回运行版本、Mac 环境、可用工具及批准通道 |
| `rules list` | 列出已启用和待研究规则及覆盖范围 |
| `scan` | 扫描默认位置；支持指定类别、项目根目录和明确路径 |
| `inspect` | 返回选中对象的受限元数据、布局及规则缺口 |
| `plan` | 根据扫描 ID 和目标 ID 清单生成不可变计划 |
| `apply` | 获取批量批准，执行计划并保存逐项收据 |
| `report` | 从扫描、计划或收据生成 HTML、Markdown |

命令输出带版本的 JSON。进度写入 stderr；大量清单保存到本地文件，stdout 返回摘要与文件位置，避免把整个磁盘目录清单灌入模型上下文。

扫描记录必须区分：

- 判断：`disposable / retain / investigate`
- 执行方式：`online / coordinated / after_task / unsupported`
- 测量是否完整及错误原因
- 默认是否选中
- 规则、证据、影响和费用判断

执行结果使用 `completed / pending / failed / skipped`，不得用“可清”冒充“已经清理”。

### 本地与连接器调用

本地客户端直接调用已安装入口。网页端通过连接器完成能力检查、原始包传输、校验、执行及结果取回。

连接器必须支持文件传输、命令执行、长任务状态查询和报告读取。首次启动只能使用发布包附带的代码；禁止模型临时编写替代清理脚本。传输采用原始字节或分块 Base64，并验证完整包哈希；中断或校验失败的包不得执行。

首次调用必须返回实际加载的技能版本、规则版本和包摘要。找不到目标版本时不得静默回退旧版。

宿主适配只处理工具名称、参数映射和文件传输，不改变扫描与删除语义。

## 4. 扫描、批准、执行与报告行为

### 扫描

- 默认仅扫描固定入口；项目发现限制在用户选择的根目录。
- 默认项目发现深度为 6；单次发现预算为 50,000 个元数据条目、180 秒。单目标测量预算为 50,000 个条目、30 秒。
- 超限、权限错误和布局不支持必须返回部分结果及具体原因，提供缩小范围或继续扫描入口。
- 路径与父子目标去重；可识别的硬链接按设备和 inode 避免重复计量。APFS 克隆不承诺按占用值释放同等空间。
- 零占用对象保留覆盖记录，默认隐藏，不生成无价值删除动作。
- 符号链接不跟随；FIFO、socket 等特殊对象单独记录。已支持普通文件清理的规则不得因为一个特殊对象放弃整个缓存目录。
- 默认不读取源码正文、会话正文、凭据、Shell 快照内容或命令历史。仅读取规则指定的有限 manifest 字段和元数据。

### 计划与批准

计划封存精确目标或明确的原生维护域、动作、影响、规则版本、目标身份和摘要。

扫描到规划之间发生变化时：独立普通文件缓存可以重新测量后进入待批准计划；身份被替换或无法安全重置的对象单独标记待办，其他目标继续规划。

只进行一次批量批准：

1. 宿主有可验证、绑定计划摘要的人工批准事件时使用该事件。
2. 否则由 Mac 原生对话框确认。
3. 无图形通道时使用真人交互终端；不可用则保持预览。

批准有效期默认 30 分钟。AI 不得代点确认、输入确认口令或填写 `approved=true` 绕过批准。新增目标或扩大影响需要重新批准。

### 执行

首版仅提供三类类型化动作：清理已批准文件、调用原生缓存维护接口、回收已验证的安装暂存或旧版本。

- 普通在线缓存保留目录，删除批准清单中身份仍匹配的文件；新增、修改或被替换的文件留到下次。
- 数据库缓存采用专用完整重置协议，不独立删除 WAL/SHM。
- 原生工具的锁和并发协议由适配器处理，不使用全局进程名阻断。
- 单项等待最多 30 秒，超时记为待办并继续其他目标；不主动关闭应用、结束任务或循环追删重建缓存。
- 执行前复核目标及父路径身份；单项变化、失败或取消不得扩大范围。
- 收据逐项落盘；重试不重复执行已完成动作。中断时处于不确定状态的动作先复核，不盲目重跑。

### 报告

固定本地模板生成 HTML 与 Markdown，内容来自核心数据。

主视图按应用、AI 客户端、开发项目分组，分别显示现在可处理、等待处理、保留或待研究；同时显示已扫描位置、空位置、失败位置和未支持布局。

每项可展开用途、路径、规则依据、删除影响、恢复方式及费用判断。选择结果只导出目标 ID，由核心重新生成计划；HTML 本身不能批准或执行删除。

执行后分别展示目标处理量、残留量和卷空闲空间变化。开放文件、快照及其他程序的并发写入可能使数值不同，不将差值全部归因于清理。

报告不加载外部资源，动态文本转义；支持明暗主题、320 像素窄屏和键盘操作。宿主无法展示 HTML 时返回 Markdown。分享版本脱敏用户名、项目路径及内部文件名。

## 5. 验收、交付与开发顺序

### 必须通过的验收

| 场景 | 通过标准 |
|---|---|
| 固定规则覆盖 | 各启用规则的正例均被发现；相邻配置、会话和唯一内容不进入删除计划 |
| 高成本、共享、近期缓存 | 默认选中；不因本地重建成本取消资格 |
| 模型费用依赖 | 已知增加费用的对象保留；具体依赖未查明的对象不默认选中 |
| 活动目标 | 在线协议不要求退出应用；锁冲突只影响相关动作 |
| 动态缓存 | 单项变化不再导致整批计划失败 |
| 特殊文件 | FIFO、socket 不导致其他独立普通缓存漏扫 |
| 空目录与重复目标 | 零占用对象不挤占主报告；父子、重复目标不重复计量 |
| 路径与批准 | symlink、路径替换、计划篡改、过期批准和提示注入不能扩大范围 |
| 部分失败与中断 | 收据准确；取消停止后续动作；重试不重复处理已完成项 |
| 跨宿主一致性 | 相同 fixture 和规则包产生相同候选、选择与动作语义 |
| 安装与传输 | 冷启动、传输中断、错误版本及能力缺失均有明确结果 |
| 报告真实性 | 预估占用、执行量和卷空闲变化不混淆 |

历史实测问题必须纳入回归：Codex 暂存的真实 `payload/` 布局、Cursor 缺少 `current` 链接、活动缓存阻断整批计划、网易云 IPC 对象造成整目录漏扫、大量零占用项。

真实机器只用于只读覆盖核查；自动删除测试全部使用可丢弃 fixture。人工批准测试与模拟批准测试分别记录，不能将模拟结果称为原生批准验收。

发布至少验证一个本地编程客户端和一个 ChatGPT 网页版＋Mac 连接器组合。仅通过连接器 API 测试不足以宣称网页端安装和展示流程通过。兼容性表只列实测组合，其他客户端按能力契约接入。

### 交付物与顺序

交付技能包、完整性清单、规则覆盖表、宿主安装说明、测试结果和已知限制。旧发布包保持不变；新规范文档的版本不等于软件发布版本。

开发顺序固定为：

1. 建立规则文件契约，完成三类首批规则的依据与 fixture。
2. 实现定向扫描、覆盖统计和受限调查。
3. 实现批量计划、批准、类型化执行及收据。
4. 实现真实报告和本地／连接器适配。
5. 完成两种宿主的安装到收据全流程验收，再生成发布包。

完成标准是：**三类范围有明确覆盖、已启用规则能真实执行、未覆盖与失败可解释、不同宿主结果一致。** 不以其他清理软件最终显示“零垃圾”作为验收指标。
