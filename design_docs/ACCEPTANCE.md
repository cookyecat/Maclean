# 第二部分的验证记录与正式实现验收

日期：2026-10-19；规则库版本：1.0.0。

## 本次已经完成

本次交付的是开发文档、规则数据与参考决策用例，**没有替换 v2.1.0 运行时，没有执行用户真实缓存清理，也没有通过这些附件授予任何删除权限**。

- 规则数据包含 56 条：27 条 ready、17 条 research、12 条 protected；每条均有稳定 ID、路径、用途、动作/保留原因、来源及验证范围。
- 校验器检查规则标识、模式边界、字段枚举、根/事实/协议/来源引用、非就绪规则无执行动作等契约。
- 125 个显式合成路径/证据用例通过，覆盖全部 56 条规则的匹配或发现预期。Cursor worker 待研究位置位于受保护的 User 树中，测试同时验证“可发现，但不获删除授权”。
- 正反例覆盖标准 Library 域、固定应用叶项、自定义根、项目局部缓存、Next fetch 响应保护、pytest 插件数据、费用依赖、保护优先级、专用协议禁止回退、0 字节、布局缺证、活动目标与锁等待。
- 用例也验证路径段边界、词面路径穿越拒绝、未跟踪源码旁的 Python 字节码、跟踪项保留以及 `.venv` 中的依赖保护。
- 匹配器只读取相邻 JSON，以合成布尔事实模拟适配器输入。所谓 symlink/identity_changed 等用例验证的是**证据到决策**的契约，不是 macOS 文件系统竞态或身份探针实现。
- `RULES.md` 和 `SOURCES.md` 从 JSON 生成，全文列出全部选择器，避免手写目录表与机器数据分叉。

机器结果见 [VALIDATION.json](VALIDATION.json)。复现方式：

```sh
# 仓库根目录
python3 docs/scan-catalog/validate_catalog.py

# 独立资料包解压后，在资料目录中
python3 validate_catalog.py
```

这 125 个用例不是“125 项真实清理测试”。本次未运行生产引擎的删除回归，也不复用历史版本通过的测试数来宣称新规则已完成验收。

## 研究项转正条件

`research` 不是“用户确认一下就变成安全”。每项缺口在 `catalog.json.rules[].gap` 中列明。实施者应完成对应来源研究、协议实现、正反 fixture 和实际支持版本测试，再提升规则版本并发布。

对 Codex daemon，需要复现对应源码的选择历史、迁移状态、运行身份以及生命周期/安装锁协议；不能用目录年龄或“保留两个最高版本”替代。桌面安装暂存还需要单独确认其安装器。对 Cursor worker，已观察路径没有可依赖的 current 链接，必须找到实际消费者和回退关系。

## 资料包完整性

独立 ZIP 包名为 `maclean-scan-catalog-v1.0.0.zip`，附同名 `.sha256`。包内 `MANIFEST.json` 列明每个资料文件的 SHA-256，不包含自身摘要。摘要用于发现传输损坏/意外修改，不是来源签名或清理授权。

历史 v1.3.x、v2.0.0、v2.1.0 技能 ZIP 均不由本次文档交付重建。正式实现应在自己的版本发布中记录实际规则版本与验收证据。
